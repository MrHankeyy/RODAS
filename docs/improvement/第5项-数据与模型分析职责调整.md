# 第 5 项：数据与模型分析职责调整

讨论及实施日期：2026-10-21。状态：用户同意方案，已实施，待界面验收。下面保留核查依据，实施结果见文末。

## 用户提出的方向

- 数据管理当前内容偏少，应承接设计优化中与原始数据准备、检查和分析有关的功能。
- 以“只分析数据、不做拟合、田口／析因筛选／代理模型与鲁棒优化三条主线共用”为前移标准。
- 将模块四的数据准备放到模块三，核查“模型与数据—统计诊断”及其他分析工具，减少模块四内容。
- 本项与第 6 项完整度检测位置、第 7 项数据管理内容、第 8 项页面跳转逻辑联动，不能据此将相关条目标为已完成。

## 核查中的关键区别

“不执行拟合”与“不依赖已拟合模型”不同。当前 WorkbenchDiagnostics 本身不拟合，但输入是已经建好的模型上下文，大部分输出包含预测、残差、拟合检验、系数区间或模型约束核验，不能作为纯数据工具整体前移。

当前“仅建模与统计分析”按钮确实会先建模：OptimizationController.run_statistics → _prepare_context → 响应面拟合／代理训练或读取已有模型 → _update_analysis。它表示“不执行鲁棒优化”，不表示“不拟合”。

## 现有功能的建议归属

| 当前位置／内容 | 数据来源 | 建议归属 |
|---|---|---|
| 方案／结果汇总中的方法、试验次数、采样方式 | 项目与试验方案 | 可在模块三的数据概况展示，模块四只保留必要上下文摘要 |
| 方案／结果汇总中的数据准备、响应完整度 | 原始试验矩阵 | 迁至模块三作为主要入口，模块四保留简短状态及前往数据管理的入口即可 |
| 统计诊断中的数据概览 | descriptive(project)，直接读取实测响应 | 迁至模块三；解除必须先有模型上下文的界面限制 |
| 拟合统计、R²、误差指标 | 观测与模型预测 | 留在模块四 |
| 系数与区间、杠杆值、Cook 距离、逐点残差 | 回归模型与观测数据 | 留在模块四 |
| 诊断图与统计解释 | 当前均围绕预测和残差 | 留在模块四，不能因图表绘制时未拟合而整体移动 |
| 显著性／LOF | 回归模型、残差及重复点纯误差 | 留在模块四 |
| 交叉验证与残差 | 训练／验证结果 | 留在模块四 |
| 模型提取 | 已训练预测器、回归系数、编码关系 | 留在模块四；纯输入范围信息可由模块三数据概况展示 |
| 筛选主效应、混杂解释 | 析因／筛选专用设计和响应分析 | 留在模块四，属于主线专属设计分析 |
| 田口水平响应、S/N、候选水平 | 田口专用内外表分组和目标定义 | 留在模块四；即便不拟合，也不属于三条主线共有的基础数据处理 |
| 参数取值、容差贡献、鲁棒优化 | 已拟合模型及优化结果 | 留在模块四 |
| 最陡上升、EVOP、自适应 AOFAT | 当前实现均调用模型驱动的 local_search | 留在模块四 |
| 设计点与约束核验 | 模型预测及不确定性传播 | 留在模块四；不能等同于检查已有实测值是否越限 |
| CSV／JSON／图形导出 | 取决于导出对象 | 原始数据及原始数据统计导出放三；模型诊断与优化结果导出留四 |

已有描述统计包括：有效数、缺失／无效数、最小值、Q1、中位数、Q3、最大值、均值、样本标准差、IQR、偏度、超额峰度。目前是按响应统计，不应声称已经支持全部因子列。

## 建议的模块三结构（待确认）

1. **试验数据**：现有矩阵读取、CSV 导入导出、响应编辑与保存。
2. **数据检查**：迁入完整度及有效性状态，展示问题位置。因子列的缺失／无效、重复设置、常量列等检查可随后扩展，不能当作现有已完成能力。
3. **描述统计**：迁入现有数据概览，直接对当前保存的数据计算，不要求先拟合，不要求所有响应列已经补齐；每项显示有效样本数，不足以计算的指标明确标为不可估计。

数据分布图（直方图、箱线图、观测值随序号变化）、输入与响应散点图可作为后续增强建议；当前模块四的残差图不能直接改名当作原始数据分布图。相关性也尚非现有工具，不列作本次迁移成果。

如增加重复试验统计，应按完整的相关输入设置分组；田口同一内表设置下改变噪声因子的观测不能直接当成所有输入相同的重复试验。重复试验统计可独立于模型；失拟检验及残差仍依赖模型。

## 建议的模块四调整（待确认）

- 汇总页移走数据准备详细表，只保留分析就绪／数据需修正状态，避免原样复制两个数据准备页面。
- 当前统计诊断拆出原始数据概览，其余聚焦模型诊断和设计核验，可讨论更明确的名称。
- “仅建模与统计分析”保留在四，建议改成“建立模型与检验”或“建模与模型诊断”；模块三的动作则使用“数据检查／统计”，清楚区分原始数据统计与拟合后检验。
- 三条主线共同使用模块三，模块四仍按主线提供筛选、田口、模型与优化功能。

## 实施时需要保持的行为

- 明确分析的是已保存的数据还是当前编辑草稿。建议先沿用现有保存边界，并在编辑后提示统计待刷新，避免把旧统计误当成当前输入。
- 输入／响应变动后，数据统计需刷新，旧模型和优化结果按已有 ProjectService 规则失效。
- 原始数据检查或描述统计不得调用训练、拟合、交叉验证或优化。
- 模型诊断中的残差 Q-Q、预测对实测图、系数区间保留其原有模型来源；不混入原始数据统计。
- 三条主线在拟合前都能使用迁入的数据功能，且未完成的数据也能查看有效部分及缺失情况。

## 已确认并实施的结果

- 五个模块标题下的灰色说明不再常驻显示，改在标题和顶部模块按钮悬停时显示。
- 数据管理的当前方法、试验次数和采样方式放入“当前方案”框；删除原表格边框上的“试验数据 · 因子列只读，响应列可编辑”文案，读写说明移至表格悬停提示。
- 数据管理分为试验数据、数据检查、描述统计三个页面，直接复用 ResultsWorkspace / ResultTabs。公共导航新增可选分组参数，模块四原有分组仍保留。
- 完整度进度表从模块四迁到数据检查；共享 data_overview 计算完整度与方案摘要，列出缺失、非数字、非有限响应所在数据行，双击可回到表格定位。
- 原始描述统计复用现有 descriptive(project)，不调用训练或拟合，支持三条主线、部分缺失数据、有效样本不足时的不可估计显示及统计 CSV 导出。
- 数据检查和统计以已保存数据为准。草稿修改后明确提示未保存；切换子页面或离开后返回保留草稿，保存后刷新统计并按原规则使旧模型结果失效。新的数据集或空数据集会刷新表格和统计。
- 模块四移除完整度详情和模型诊断中的“数据概览”页，保留简单状态及“前往数据管理”入口。拟合统计、系数、残差及设计点核验继续留在四。
- 原“仅建模与统计分析”改名为“建模与模型诊断”；“统计诊断与导出”改名为“模型诊断与核验”。未更改模型算法、模型检验或优化的计算含义。
- 描述统计与模型诊断共用 fill_records 表格填充函数，不复制一套相同单元格渲染逻辑。
- 本次不新增分布图、相关性分析或其他尚未确认的工具，不恢复设置持久化，不执行此前暂缓的独立代码瘦身计划。
